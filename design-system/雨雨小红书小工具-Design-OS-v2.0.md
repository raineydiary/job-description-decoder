# 雨雨小红书小工具 Design OS v2.0

> 一套可替换视觉 DNA、但保持同一创作品牌气质的小工具母规范。  
> Y2K 像素 BB 机只是其中一个 Skin，不是系统本身。

## 1. 系统结构

每个小工具由两层组成：

### A. 不变的雨雨产品骨架

这一层决定“是不是雨雨的小工具”，不随风格更换：

1. **一眼看懂**：3 秒内知道这是什么、要做什么。
2. **一步开玩**：无注册、无教程、无冗长开场，核心操作只有一个。
3. **有一个意外**：结果、文案或动画至少有一处让人想笑、想截图或想发给朋友。
4. **抽象但准确**：可以有梗，但必须来自真实语境，不说泛化 AI 黑话。
5. **像一个东西**：界面有明确世界观或物件隐喻，不是把信息放进几张通用卡片。
6. **小而完整**：优先做适合一次体验的封闭回路，不为了“像产品”堆功能。

### B. 可替换的视觉 DNA

这一层决定每个小工具的个性。每次可以换风格，但必须成套替换，不只换一组颜色。

```text
雨雨产品骨架
├── 核心行为：用户输入 → 一个主操作 → 可分享结果
├── 首屏结构：定义 → 操作 → 次玩法
├── 文案人格：直接、懂梗、不说教
└── 验收方法：先模拟 → 确认 → 实装 → 真机尺寸 QA

可替换视觉 DNA
├── 世界观 / 物件隐喻
├── 形状语法
├── 色彩角色
├── 字体组合
├── 材质与纹理
├── 插画 / 角色语言
└── 动效物理
```

## 2. 通用产品骨架

### 2.1 一页一句话

立项前必须补完：

> 用户带着 **______** 进来，按下 **______**，得到一份 **______**，并因为 **______** 想截图或分享。

如果无法用一句话补完，说明功能还没有收敛。

### 2.2 首屏四层

| 层级 | 要回答的问题 | 要求 |
| --- | --- | --- |
| 01 身份 | 这是什么？ | 小标签 + 一句有情绪的大标题 |
| 02 核心机制 | 我怎么玩？ | 输入区、状态区与唯一主 CTA |
| 03 反馈 | 点了会发生什么？ | 按钮、状态或角色给即时反应 |
| 04 诱饵 | 还有什么好玩？ | 首屏底部露出盲盒、换壳、隐藏频道等次入口 |

默认在 `402 × 874 CSS px` 中验收。主 CTA 完整可见；次玩法尽量完整露出，至少要露出到让用户知道可以继续玩。

### 2.3 密度公式

紧凑不等于缩小一切：

1. 先删掉无信息价值的空白。
2. 再压缩区块间距。
3. 再缩短标题和说明。
4. 最后才缩字号或按钮。

推荐间距节奏：

- 页面左右留白：20px；360px 窄屏可降至 12px。
- 大区块间：16–24px。
- 区域内标题到内容：6–12px。
- 密切关联的标签与值：4–8px。
- 触摸按钮高度：不小于 44px；主 CTA 建议 50–56px。

### 2.4 交互回路

标准回路为：

```text
默认态
  ↓ 一次明确操作
处理态（有视觉反馈）
  ↓
结果态
  ├── 继续玩：换一条 / 重开 / 抽一个
  └── 离开：截图 / 分享 / 带走一句话
```

- 处理态应该是世界观内的反馈，例如“正在破译”、“正在盖章”、“正在装订”，不是通用 Loading spinner。
- 结果必须能独立被看懂，不依赖用户记住前一页内容。
- 结果较多时使用明确的左右翻页与 `01 / 05` 进度，不把所有结果堆在一屏。

## 3. 文案系统：风格可换，人格不变

### 3.1 固定人格

雨雨小工具的声音是：

- 懂中文互联网和年轻人语境的同龄朋友。
- 直接、好笑、略损，但不恶意贬低用户、公司或群体。
- 不卖弄方法论，不先说安全提示，不用长篇解释破坏节奏。
- 说完梗以后能留下一点有用的判断、问题或提示。

### 3.2 文案四层

| 层级 | 作用 | 写法 |
| --- | --- | --- |
| 门头 | 定义世界观 | 2–6 个字，如“秋招破译局” |
| 钩子 | 让用户产生自我投射 | “JD 写得很漂亮” |
| 主句 | 把焦虑变成玩法 | “实际真相是？” |
| 结果 | 形成截图价值 | 具体、口语化、单独看也好笑 |

自查问题：

- 这句话换到任何 AI 应用里都能用吗？如果能，重写。
- 用户会不会说“对，就是这个意思”？如果不会，还不够准。
- 截掉 Logo 以后，这句结果还有分享价值吗？如果没有，还不够强。

## 4. 视觉 DNA 的标准化定义

每个新工具在设计前必须填写一张 **Visual DNA Card**。不允许只写“高级感”、“小红书风”或“Y2K”一个词就开始出图。

### 4.1 Visual DNA Card

```markdown
# Visual DNA Card

- DNA 名称：
- 世界观一句话：
- 核心物件隐喻：
- 想让人感到的 3 个形容词：
- 明确不要的 3 个形容词：

- 形状语法：圆 / 方 / 不规则 / 机械 / 纸张 / 手绘
- 线条语法：粗线 / 细线 / 铅笔 / 油墨 / 像素 / 无轮廓
- 表面材质：
- 主色角色：背景 / 容器 / 主 CTA / 文字 / 装饰
- 字体组合：展示字 / 正文字 / 数字字
- 图像语言：人物 / 道具 / 摄影 / 插画 / 纯排版
- 装饰上限：首屏最多几个，占画面比例多少
- 动效物理：弹 / 跳 / 抽帧 / 滑 / 翻页 / 盖章 / 撕纸
- 循环动效节奏：
- 主操作的世界观名称：
- 结果的世界观名称：
```

### 4.2 色彩应使用“角色”而不是“固定色值”

不同 DNA 不需要使用同一组蓝、粉、绿，但都应定义以下功能色：

| Token | 作用 | 要求 |
| --- | --- | --- |
| `--canvas` | 世界背景 | 承载风格，不与主容器抢对比 |
| `--surface` | 主容器 | 与背景有明确材质或明度差 |
| `--ink` | 主文字 | 满足移动端阅读对比 |
| `--accent` | 主 CTA | 全页最明确的行动颜色 |
| `--signal` | 状态 / 结果 | 用于进度、数字、提醒和成功反馈 |
| `--sticker-1/2/3` | 装饰 | 可丰富，但不能取代 CTA 的引导作用 |

每个 DNA 必须用同一套角色 Token 重新选色，而不是复制上一个项目的色值。

### 4.3 形状、字体、材质和动效必须是同一个故事

错误示例：报纸世界观 + 玻璃拟态卡片 + 像素字 + 果冻弹跳。

正确示例：报纸世界观 + 分栏和铅印边线 + 标题黑体 / 宋体 + 翻页、对齐、盖章动效。

一套 DNA 应该能回答：

- 这个世界是由什么材料做的？
- 它的边缘是软的、硬的，还是被手工撕出来的？
- 里面的东西是怎么移动的？
- 这个世界会使用什么字体写字？

如果四个答案不在同一个故事里，DNA 还没有成型。

## 5. 可直接替换的 5 套视觉 DNA

### DNA 01：Y2K 掌上机器

- **适合**：破译器、数值测试、重开模拟器、游戏化工具。
- **物件**：BB 机、掌机、电子词典、老式手机。
- **语法**：像素字、彩色塑料、LCD、粗边和硬阴影。
- **动效**：抽帧、跳动、闪屏、按键下沉。
- **避免**：苹果风精致感、通用游戏 HUD、大面积霓虹。

### DNA 02：校园地下小报 / Editorial Zine

- **适合**：职场吐槽、观点测试、生存指南、人格标签。
- **物件**：校园报纸、二手杂志、社团传单、复印小册子。
- **语法**：黑白网点、分栏、粗黑标题、手写批注、荧光笔划线。
- **动效**：翻页、剪报横向推入、盖章、打字机逐字。
- **避免**：干净商业画册、过度小清新、规整无性格的 Grid。

### DNA 03：私人侦探档案室

- **适合**：选 Offer、人际关系、风险判断、反向测谎、信息梳理。
- **物件**：档案袋、证物牌、线索墙、录音带、调查表。
- **语法**：米白纸、黑墨、暗红印章、打字机字体、手写圈选。
- **动效**：抽出档案、拉线连接、翻面、盖“待定”印。
- **避免**：严肃警政写实、血腥罪案感、过暗导致移动端不可读。

### DNA 04：手账贴纸实验本

- **适合**：选择题、愿望清单、轻度治愈、日记、生活观察。
- **物件**：手账本、标签纸、相片角贴、彩色记号笔、贴纸包。
- **语法**：纸张纤维、半透明胶带、手写字、彩色印章、留有呼吸感的拼贴。
- **动效**：贴上、撕下、翻页、手写线出现。
- **避免**：幼儿园卡通、全粉色、贴纸无限堆叠导致失去重点。

### DNA 05：奇怪实验室 / Specimen Lab

- **适合**：战力值、能力配方、人格分析、岗位匹配、结果生成。
- **物件**：样本盒、药片板、显微镜、配方单、实验记录仪。
- **语法**：骨白、实验绿、警戒橙、透明塑料、编号标签、精密网格。
- **动效**：滴落、扫描、称重、样本弹出、数值跳字。
- **避免**：通用科幻蓝 HUD、医疗恐惧、复杂仿真 3D 仪器。

## 6. 如何选择 DNA

### 6.1 先选行为隐喻，再选审美

| 用户在做什么 | 更合适的物件隐喻 |
| --- | --- |
| 破解、翻译、接收信息 | BB 机、收音机、电报机 |
| 对比、查证、找风险 | 侦探档案、证物板、审讯记录 |
| 测量、评分、生成配方 | 实验室、测量仪、样本盒 |
| 随机、抽取、重开 | 扭蛋机、卡带、存档器、马戏团转盘 |
| 记录、收藏、温柔反思 | 手账、拍立得、信箱、贴纸本 |
| 爆料、吐槽、发表观点 | 小报、校园广播、复印传单 |

如果“换一个很好看的风格”会破坏用户行为与物件之间的关系，这个风格就不该选。

### 6.2 三方案提案制

每个新项目开始时，只提 3 个视觉 DNA：

1. **直觉方案**：与产品功能最直接的物件隐喻。
2. **意外方案**：更抽象、更有分享感，但仍能解释为什么。
3. **克制方案**：以排版、文字和轻材质为主，用于测试是否真的需要角色和重容器。

每个方案必须同时给出：世界观一句话、物件隐喻、5 个色彩 Token、2 种字体角色、3 个动效动词和一张手机首屏模拟。

## 7. 可迁移实例

| 工具 | 可选 DNA | 主操作可怎么变 |
| --- | --- | --- |
| 秋招 JD 黑话翻译器 | Y2K 掌上机器 | “破译这段话” |
| 秋招 JD 黑话翻译器 | 校园地下小报 | “排版真相头条” |
| Offer 理性决策 | 私人侦探档案室 | “提交两份证词”，结果为“待定案件报告” |
| 秋招简历战力值 | 奇怪实验室 | “送检这份简历”，结果为“能力样本单” |
| 秋招重开模拟器 | Y2K 卡带 / 存档器 | “删档重开” |
| 秋招重开模拟器 | 校园地下小报 | “重印你的秋招头版” |

同一个功能换 DNA 时，必须同时改变容器、操作命名、反馈、结果格式和动效。只换颜色不算换 DNA。

## 8. 与 AI / 设计师的标准交付流程

### Phase 1：产品收敛

- 输出一句话闭环、主用户、一个主 CTA、一个分享点。
- 删除首版不必要的登录、OCR、联网、上传或系统权限。
- 确定最少数量的真实内容样本，不用占位假文案支撑设计。

### Phase 2：DNA 提案

- 输出 3 张 Visual DNA Card，必须有显著不同的世界观，不是三组颜色。
- 先选物件隐喻，再选配色和字体。
- 用户选定一个 DNA 后锁定，不在后续轮次悄悄混入另一个 DNA。

### Phase 3：模拟优先

- 先输出 `402 × 874` 手机首屏模拟，标出主 CTA、次玩法和角色占位。
- 布局、角色、文案分轮确认；没有得到“OK”前，不写回正式代码。
- 修正一个区域时不顺手重做全页，避免已确认部分反复漂移。

### Phase 4：实装与 QA

- 从正式构建产物重新截图，不使用之前的模拟图代替验收。
- 检查 402px 和 360px 视口、长文本、结果态、滚动后页脚、所有按钮和所有动画。
- 图像、文字、序号和按钮要做遮挡检查；图片必须检查真透明、边界与肤色。

### Phase 5：发布

- 按小红书小工具规范生成离线 ZIP，根目录只保留一个 `index.html`。
- 无外链资源、联网请求、内联脚本、多 HTML 或未使用权限。
- 产物目录、ZIP、图标、版本号、权限和校验摘要一次性交付。

## 9. 一票否决清单

以下任意一项存在，都不算可交付：

- 没有先给用户看手机模拟就直接修改定稿页。
- 视觉只是“换了配色的通用卡片”，没有物件隐喻或形状语法。
- 一套风格里混入了不相关的字体、材质或动效物理。
- 装饰图、角色或手机裁切遮住了内容和交互。
- 角色是假透明、有棋盘格、卡边、被背景染色，或只有部分动画生效。
- 文案换到其他 AI 工具也完全成立，或只把用户原话改写了一遍。
- 用缩小字号代替布局取舍，或为了塞满首屏破坏可读性。
- 未真实点击主 CTA、次玩法和翻页就宣称功能或动画已通过。

## 10. 可直接复制的启动 Prompt

> 请按《雨雨小红书小工具 Design OS》开发这个小工具。先用一句话定义“用户输入—唯一主操作—可分享结果”，并删掉首版非必要功能。然后提供 3 套显著不同的 Visual DNA Card：一套直觉方案、一套意外方案、一套克制方案。每套必须包含世界观、物件隐喻、形状语法、色彩 Token、字体角色、材质、图像语言和动效物理，不能只换配色。待我选定 DNA 后，先输出 402×874 iPhone 首屏模拟图，检查主 CTA、次玩法、文字和装饰遮挡。只有在我确认 OK 后才能写回正式代码。实装后从真实构建产物重新截图，真实触发主流程、翻页与动效，然后再完成小红书 ZIP 校验和打包。

## 11. 版本关系

- `Design OS v2.0`：上层可迁移母规范，定义产品骨架与 Visual DNA 方法。
- `雨雨小红书小工具设计规范 v1.0`：`Y2K 掌上机器` DNA 的第一份实例化 Skin。
- 以后每开发一套稳定新风格，可增加一份独立 DNA Skin，不改动 Design OS 的核心骨架。
